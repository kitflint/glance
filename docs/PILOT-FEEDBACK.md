# Pilot feedback worksheet

Use one blank copy per participant. Run three separate sessions with independent participants, including at least one novice and one experienced developer. Use disposable synthetic boards and follow the [first-use checklist](FIRST-USE-CHECKLIST.md). Use participant codes for feedback and omit names, contact details, private paths, launch links and credentials.

- Participant code
- Experience level, optional
- OS, Node, npm and browser versions, optional
- Private source package SHA-256
- Consent to retain feedback, yes or no. Keep feedback only with explicit consent.

## Before explanation

Ask the participant to describe what they see in their own words. Record what they identify as the project stage, a blocker and the next action. Ask what “accepted for stated scope” means and what would tell them the project was released. Record their answers before explaining the labels.

## Independent tasks

Ask the participant to attempt each task independently first. Record the outcome, any error or blocking step, and whether they requested help. Record any help given and the result after help.

## After the tasks

Ask the same four questions again, then ask the participant to explain one task's progress using only the board. Note whether their explanation matches the board's counts, evidence and freshness labels.

The pilot covers the local board and, for participants with a GitHub account, one GitHub starting journey on a test repository they own. Assistant-client tasks are optional and limited to Claude Desktop or Claude Code.
